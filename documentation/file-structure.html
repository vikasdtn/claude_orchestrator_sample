Project File Structure

📘 What This Document Covers

Purpose: This document provides a comprehensive listing of all project files, their purposes, and deployment targets.

Who should use this: Developers, DevOps engineers, and anyone needing to understand the project structure and deployment architecture.

What you'll learn: Complete file inventory, purpose of each file, AWS deployment targets, and container grouping for orchestrator and utility agents.

Root Level Files

File Purpose AWS Service / Deployment
.gitignore Git ignore patterns for Python, Docker, IDE files Development only (not deployed)
docker-compose.yml Local development environment configuration Development only (not deployed)
Dockerfile.base Base Docker image for all agents Used during build, pushed to ECR
pyproject.toml Python project configuration and dependencies Development only (not deployed)
README.md Project overview and quick start guide Documentation only (not deployed)

Shared Module

File Purpose AWS Service / Deployment
shared/__init__.py Python package initialization Included in all agent containers
shared/models.py Pydantic data models for requests, responses, and domain objects Included in all agent containers
shared/base_agent.py Abstract base class for utility agents with common logic Included in utility agent containers
shared/claude_client.py AWS Bedrock client for Claude model invocations Included in all agent containers
shared/gateway_client.py AgentCore Gateway client for external system integration Included in utility agent containers
shared/requirements.txt Python dependencies for shared module Used during Docker build

Summary

The project consists of:

  • 1 Orchestrator Container - Coordinates all utility agents and manages execution plans
  • 9 Utility Agent Containers - Each specialized for a specific domain (billing, FAQ, sales, etc.)
  • Shared Module - Common code included in all containers
  • Infrastructure as Code - Terraform files to provision AWS resources
  • Build Scripts - Automation for building and deploying containers
  • Test Suite - Comprehensive unit tests for all components

All containers are pushed to Amazon ECR and deployed to AWS Bedrock AgentCore Runtime where they run as serverless, auto-scaling agent runtimes.
